## Open items

- **Accepted exception: audit list reads user names.** `AuditEntry.userName` is a read-only `@Formula` that joins `users` to show the sign-in name (review S4, 25-10-2026). The foreign key `audit_log.user_id` already ties the two tables; writes go through `CurrentUserProvider`. Revisit if the security module changes its user table.
- **Audit masking for money fields (fee receipts closed by F3, 2026-10-28; staff and payroll still open).** The masking rule shows only the last 4 characters of sensitive fields. For salary and fee amounts that would hide the before/after values that constitution Principle III requires. Decide the rule for amount fields when F5 (staff) and F8 (payroll) are specified.
- **Seed values for `affects_fees`.** Ask the school which categories carry a separate fee (client questions, fee section).
- **First-run credentials file** (`credentials-first-run.txt`): who delivers it to the school, where it is stored, and who deletes it after first sign-in. Decide in the installer feature (F11).
- **No current year between two years.** The admin is forced to create the next year (decided 24-10-2026). Year rollover (F4) needs no "make current" step: the new year becomes current on its start date. F1 and F2 specs should also refuse to run without a current year.
- **School PC: target is Windows 10 (decided 25-10-2026), 4 GB RAM, one computer.** (It is Windows 8 today; the school will move to Windows 10.) Docker Desktop, current Chrome/Edge and (probably) current Java and PostgreSQL do not support Windows 8. Plan: tell the school to upgrade to Windows 10 or buy a small PC with 8 GB RAM, an SSD and Windows 11 before go-live. F11 builds one installer that bundles Java and PostgreSQL as Windows services (no Docker, no separate PostgreSQL install), limits memory, adds a desktop shortcut, and sets up the first-run credentials file and a weekly USB backup. Verify the vendors' supported Windows versions before promising anything. Ask the school: Windows 8 or 8.1, 32 or 64 bit.
- **How the Google Form data reaches the app.** The PC may be offline or have no Google credentials. Recommended: the form is created with columns we define; the admin downloads the responses as an Excel or CSV file and uploads it into the approval page. Direct Google Sheets sync is possible later. Decided 2026-10-31: the form is built inside F4; the remaining details are in the F4 open items below.
- **Possible use of the form for existing students.** Since no Excel exists, the same form could collect data for existing students. Decide with the school.
- **Existing students entry volume.** All current students are typed in by the admin; consider a faster entry screen (keyboard-friendly, Save and add next).
- **No cancel/edit means a wrong receipt cannot be fixed in the app.** Proposed: a documented developer-assisted correction runbook (like the password reset) with an audit entry, and a clear review step in the confirmation dialog. Confirm in F3 spec review.
- **F3 defaults to confirm:** one-way "not cleared" (a re-paid cheque gets a new receipt); the year-fee row is limited to the year's remaining fee, the registration row to its remaining amount; earlier years' pending is paid only through the previous-years receipt; receipt date may not be in the future; Left students can still pay; the fund ledger is not built in F3 (F9 reads receipts).
- **Std 12.** Std 12 has no next standard. What does the promote screen do for it (for example the students can only be marked Left, and the LC is prepared later)?
- **Students not yet promoted.** Until a student is promoted they have no class record in the new year. Decide what the Students list and fee collection show for them, and when the warning goes away (when every standard is done, or per standard).
- **Registration fee in F3.** The F3 defaults let a registration row be paid in parts ("the registration row to its remaining amount"). If the registration fee must be paid all at once, F3 should refuse a registration payment that is less than the full registration fee. Otherwise an unpaid part drops off when the year changes.
- **Form upload: file type and re-upload.** Is the file .xlsx or .csv, and does it include Google's Timestamp column? Default: both file types accepted; a row already imported (same timestamp, name and date of birth) is skipped when the same file is uploaded again.
- **Form duplicates.** The agreement flags the same name, date of birth and mobile; F1 warns on the same first, middle and last name. Which applies to form rows? Default: flag a row when either matches an existing student or another row.
- **Form photo.** The photo is uploaded by the admin (decision of 2026-10-25), so it is not a column in the Excel. Confirm the admin adds it during review or later from the profile.
- **Year, standard and division for a new admission.** Default: the admission standard comes from the form; at review the admin picks the academic year (the current year, or the next one if admitting early) and the division, and the category if the form has none.
