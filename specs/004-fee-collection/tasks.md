# Tasks: Fee Collection and Receipts (F3)

**Input**: Design documents from `/specs/004-fee-collection/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/openapi.yaml, quickstart.md. F2 (`003-fees`, migration `V7`) is on `main` and on this branch (`6fa7d7e`).

**Tests**: Included, written together with the code in the same task (constitution Principle VIII, FR-024): in every task write the test first, see it fail, then write the code. Backend tests carry `@Covers("FR-xxx")`; Playwright test titles start with the FR ids. One task covers one group of files, never one class.

**Organization**: Grouped by user story. Shared plumbing (spikes, schema, lookups, exporter extra, entities, pure rules, test data) is in Phases 1 and 2. Each story has a backend task and, where it has a screen, a frontend task.

**No owner tasks**: every task here is done by Claude in the repo. Timed and size checks are automated tests with a pass or fail assertion; their results are written to `specs/004-fee-collection/quickstart-results.md`. The open questions of `plan.md` are not tasks: each task that depends on one says "default until the owner answers: ...", and the last task writes those defaults into the decision log as "proposed, awaiting owner confirmation". Nothing waits for the owner.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1 to US6, mapping to the user stories in spec.md (US1 record a payment, US2 balance and paid up to, US3 previous years, US4 cheque not cleared, US5 print, US6 register and export)
- **[PLAN MODE]**: start the task in plan mode (CLAUDE.md: money, schema), show the plan, then continue under the plan-mode approval of the session. Nothing else in this list pauses for a person.
- Commit after every task, with the FR ids in the message (CLAUDE.md). Never commit to `main`. No task here pushes, tags or opens a pull request (`/finish-feature` does that).

## Path Conventions

- `BE/` = `management/src/main/java/com/admin/management/`; `BT/` = `management/src/test/java/com/admin/management/`

- `FE/` = `frontend/src/app/`; e2e specs in `frontend/e2e/`, helpers in `frontend/e2e/support/`
- Follow the nearest F0, F1 or F2 example for each kind of file (for example `BT/fees/FeeFinaliseIT.java`, `BE/fees/BroughtForwardService.java`, `BE/students/StudentTable.java`, `FE/features/fees/`)
- Synthetic data only (constitution VI). Money is `BigDecimal` and `NUMERIC(12,2)`; compare with `compareTo`, never `equals`; no `double` or `float`, in tests too
- Needed on the machine: JDK 21, PostgreSQL with the databases `admin_management_db` and `admin_management_test`, Node as in F0, port 8080 free for the Playwright run
- Names are the plan's. `BE/fees/` gains `Receipt`, `ReceiptMark`, their repositories, `FeeBalance`, `FeeBalanceService`, `PaidUpTo`, `AmountInWords`, `ReceiptService`, `ReceiptMarkService`, `ReceiptTable`, `DayTotals`, `ReceiptController`, `ReceiptListController`, `StudentFeeCollectionController`, `SchoolProperties`; `FeesAudit`, `BroughtForwardService`, `StudentFeesService`, `StudentFeesDto` change.
