# Tasks: Year Change and Admissions (F4)

**Input**: Design documents from `/specs/005-yearchange/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/openapi.yaml, quickstart.md. F3 (`004-fee-collection`, migration `V8`) is on `main` and on this branch.

**Tests**: Written together with the code in the same task (constitution Principle VIII): write the test first, see it fail, then write the code. Backend tests carry `@Covers("FR-xxx")`; Playwright and Angular test titles start with the FR id. Money and carry-forward tasks (T012, T014, T016) carry extra tests.

**Organization**: Six phases in the order you asked for. Phases 2 to 5 map to the spec's user stories (US1 year copy, US2 promotion, US3 warning, US4 carry-forward, US5 form admissions). Each phase ends with a STOP line: run `/run-tests <phase>` before starting the next.

**Format**: `- [ ] T### [P?] [US?] Description (FR ids; files)`. `[P]` = can run in parallel with the other `[P]` tasks of the same phase (different files, no dependency on an unfinished task). `[PLAN MODE]` = start in plan mode (CLAUDE.md: money, schema). `[OWNER]` = needs an answer from the owner; nothing is guessed.

**Agreement ids**: YR-01 = FR-001 to FR-005; YR-02 = FR-006 to FR-019; YR-03 = FR-020 to FR-027; STU-02 = FR-028 to FR-038.

## Path Conventions

- `BE/` = `management/src/main/java/com/admin/management/`; `BT/` = `management/src/test/java/com/admin/management/`
- Migrations: `management/src/main/resources/db/migration/` (new files `V9__year_change.sql` and `V10__correct_promotion.sql` only; V1 to V8 are never edited)
- `FE/` = `frontend/src/app/`; e2e specs in `frontend/e2e/`
- Follow the nearest F1 to F3 example for each kind of file (`BE/fees/BroughtForwardService.java`, `BE/students/StudentTable.java`, `BT/fees/ReceiptCreateIT.java`, `FE/features/fees/`)
- Synthetic data only (constitution VI). Money is `BigDecimal` and `NUMERIC(12,2)`, compared with `compareTo`; no `double` or `float`, in tests too
- Commit after every task with the FR ids in the message. Never commit to `main`. No task pushes or tags (`/finish-feature` does)

**Plan defaults used** (all confirmed by the owner on 2026-10-31 unless marked): Std 11 and 12 are one row each and the stream is on the class record; Left on the promote screen also sets the student's status to Left; a receipt with registration 0 and only a year fee stays allowed; Left students carry nothing forward; promotion needs the new year's fees finalised. Not yet confirmed: the `standards.uses_stream` flag and "same fee for both streams" (T002).
